My first idea was a Pong game on a tennis court with a particle spawner that filled the court with moths. The plan was for the ball to squish a moth whenever it hit one and leave a little goop behind on the court. I liked the idea a lot, but once I started working on it I realized it was kind of too ambitious for where I am with Unity right now. Getting the ball to react to each moth particle and then leave marks on the court was a lot more complicated than I expected, and I was spending more time stuck on the moths than actually making a game. So I scrapped that version and went back to the basics. I asked myself what I could build and still fully understand, and that turned into Pongball, which is Pong mixed with a pinball machine. It keeps the ball and paddle from the Pong tutorial we did in class, but adds [your pinball parts, like bumpers and a score], so it still feels like my own thing. I think the simpler idea was the better call, because I can actually explain every script in it.

When I added the score, I figured out there was a simple way to fit it into a script I already had, so I didn't need to make a separate script just for scoring. That helped a lot, because I had fewer scripts to keep track of and I could see the score change right where the points happen. But I also don't think it's a good habit to stick with. When the score is tucked inside another script, I could kind of lose track of where it is later on. And if I add more to that script, the score code could get mixed up with the other code and break something because I missed it. For a small game like this it works fine, but on a bigger project I would probably give the score its own script so it's easy to find.

Overall, I'm happy with where I left the project. It's a solid prototype, and everything in it is something I understand and can explain. If I ever come back to it, there's room to add onto it without having to start over.
